# 近章结构指纹与语义冷读

近章结构指纹解决的是“连续章节是否反复使用同一种叙事发动机”，不是判断作者身份，也不是要求每章都换一种花样。连续案件、审讯、仪式、倒计时和阶段攻坚天然会共享物件与步骤；只有表现层、信息交付和人物反应也长期同构时，才形成需要处理的模板感。

## 确定性证据包

长篇候选章有至少三章正式历史正文时运行：

```bash
{PYTHON} scripts/chapter_shape_gate.py \
  --project "{项目根}" --candidate "{候选正文}" \
  --chapter {N} --window 6
```

脚本只读取当前候选和 `正文/` 内最近三至十二章，输出：

- 开篇/收尾粗粒度类型与短摘录；
- 对白、问句、疑似问答对、规则句、程序词和解释词的实测密度；
- 候选与近章表面向量的相似度；
- 连续收尾类型和表面形状聚集提示；
- 固定五问语义冷读卡。

相似度只用来缩小冷读范围。它不等于结构相同，更不等于 AI 概率；所有输出均为 advisory，脚本从不自动改正文。

## 五问冷读

主 Agent 或叙事审查者必须回到正文逐章回答：

1. 近章是否反复用同一种冲突发动机，而不只是共享题材物件？
2. 配角是否只负责提出下一个规则问题，主角随后给出完整标准答案？
3. 信息是否总通过分栏、列举、公开验证或总结性对白交付？
4. 章尾钩子的事件功能是否连续同构，而不只是标点或句长相似？
5. 候选是否保留人物特有的误解、回避、私心或未解决代价？

每个“是”都必须附具体章节和段落证据；没有证据就不能升级为结构问题。

## 处置边界

- 只共享世界观物件、职业步骤或同一案件证据链：保留。
- 冲突发动机相同，但每章人物选择、代价和关系变化不同：记录理由后保留。
- 连续三章以上同时复用“配角精准提问 → 主角完整解释 → 群体接受 → 同类程序反压”：优先改候选章的信息交付方式，不回头批量重写历史章。
- 处理时先让后果、误解、行动失败或人物选择承担信息；不要为了“人味”随机加口误、脏话、无功能动作或枝节。
- 若必须重排已接纳正文，立即转入修订治理；结构指纹本身不授权修改旧章。

## 与声音画像的分工

- 已接纳声音基线：判断候选是否偏离这本书已经成立的统计范围。
- 黄金声线样本：判断候选是否远离作者精选的强样本。
- 近章结构指纹：判断最近连续章节是否复用同一种表现骨架。
- 角色声线：仍需按人物归属和语境做语义审查，首版不从书级统计自动推导。

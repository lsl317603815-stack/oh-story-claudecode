# 修订影响链与长期事实门禁

本协议适用于任何已经进入正式工程的语义修改，不限于正文回炉。修改总纲、卷纲、细纲、角色/世界设定、身世、血缘、关系、权限、物品所有权或不可逆规则时，必须执行同一套影响分析和闭环验收。

## 一、事实权威与三层记忆

### 工具与作品的解耦边界

- `skills/`、通用 Agent 模板、hooks 和检查脚本只定义字段、类别、影响算法与通过/拒绝条件，不得写入任何具体书名、角色名或剧情事实。
- 具体作品的事实只能存在该作品目录下的 `设定/`、`大纲/`、`正文/` 与 `追踪/_tracking-state.json`；派生索引也必须生成在该作品自己的 `追踪/` 内。
- 通用工具只接收 `--project {作品根目录}` 后读取当前作品；不内置项目默认值，也不跨作品共享事实 ID。

1. **静态设计层**：`设定/`、`大纲/大纲.md`、卷纲和细纲。它们表达作者计划，不能自动压过已发表正文。
2. **正文证据层**：`正文/`是读者已看见的事实。已发表正文与设计层冲突时，必须明确裁定要改哪一边，不得默认用新纲要覆盖旧正文。
3. **结构化记忆层**：`追踪/_tracking-state.json`是当前状态、长期硬事实和关系的唯一结构化权威。`长期事实.md`、`关系清单.md`、`事实档案/{实体}.md`与其他追踪 Markdown 都是工具派生视图，禁止手改。

编写新章不需把整书重读一遍：先读热上下文，再按细纲中的实体名和事实 ID 定点读角色快照、事实档案、关系清单、相关时间线/伏笔及原始证据章。这是解决“第 30 章发生过什么”的正式召回路径。

## 二、长期事实与关系的收录边界

只收录“后面不知道就会写错”且能给出来源的事实：

- 身份、血缘、亲属、婚姻、别名、传承、从属、长期合作/敌对；
- 核心物件、产业、证据的所有权或保管权；
- 世界规则、机构权限、系统代价、不可逆状态；
- 决定当前因果的历史事实。

不收录一次性对话、普通出场、短期情绪、未发生的细纲计划或无正文/设定证据的猜测。伏笔仍进 `伏笔.md`，时序/读者揭示仍进双时间线；不用长期事实重复代替它们。

每条事实必须有：稳定 ID（`K001` 通用硬事实，`R001` 关系）、类别、主体—断言—客体、单值/多值口径、作者真相状态、读者揭示状态、证据引用、相关实体和禁止误读。单值槽位如“某人/生父”、“古井/最终状态”出现两个不同值时，`tracking_commit.py` 直接拒绝提交。

## 三、修订影响关系清单

| 起点修改 | 必查向上权威 | 必查同层 | 必查向下投影 | 追踪动作 |
|---|---|---|---|---|
| 正文第 N 章 | 对应细纲、卷纲、总纲、相关设定 | N-1/N+1 正文与细纲 | 所有命中实体/事实的后续章 | `mode=revision`更新快照、伏笔、时间线、`fact_changes` |
| 细纲第 N 章 | 卷纲、总纲、相关设定 | N-1/N/N+1 细纲 | 已存在的第 N 章正文及受承诺影响后续章 | 语义已发生时必须更新结构化追踪 |
| 卷纲 | 总纲、题材/世界/角色设定 | 相邻卷交接 | 该卷全部细纲、已写正文 | 更新所有受影响长期事实与当前状态 |
| 总纲/终局 | 题材契约、世界底牌 | 主线/辅线/人物弧 | 所有受影响卷纲、细纲、正文 | 重算不可逆规则、身世、关系和终局因果 |
| 角色/身世/关系设定 | 总纲与已发表正文证据 | 关系网中所有直接相连实体 | 命中该实体的卷纲/细纲/正文 | 更新事实 ID、关系清单、实体档案和角色快照 |
| 世界规则/权限/物权 | 总纲、题材契约 | 相关机构、持有人、代价 | 所有使用或见证该规则的章节 | 更新单值事实与禁止误读，检查旧用法是否失效 |

“必查”表示必须阅读并在影响清单标记，不等于每个文件都必须改字。但只要发现口径冲突，就必须在本轮统一，不得只把它记成“以后注意”。

## 四、修订门禁操作

1. 修改前先调用只读 `revision-governor`（`phase=plan`）展开关系与事实级联；返回 `READY_TO_PLAN` 后构造计划 JSON，运行：

```text
{PYTHON} scripts/revision_guard.py plan --project {项目根} --input {计划.json} --output {项目根}/追踪/修改影响/active.json
```

`changed_files` 写本轮要改的正文/大纲/设定源文件；`affected_entities`、`affected_fact_ids`、`affected_chapters` 不得留空规避扫描。工具会把相邻章、对应细纲、总/卷纲、同实体命中文件和事实/关系派生视图展开成 `required_checks`。

`changed_files` 只能指向当前生效的正式工件；路径中带“备份”、“归档”或 `archive(s)` 的历史副本不参与当前事实裁决，也不得被当成修订源。设定修改按受影响实体定点扫描细纲与正文；总纲/卷纲修改才向下展开全部细纲。

2. 修改和主线程复核后，把实际读过的文件填入 `checked_files`。每个冲突写入 `conflicts`：`source/target/severity/issue/resolution/status`。S1/S2 不得用 `accepted` 跳过，任何 `unresolved` 都会阻断。发现计划外受影响源文件时先重跑 plan，不能在写完后只给 `changed_files` 补一行。

3. 语义修改必须通过 `tracking_commit.py commit` 或者旧 schema 的 `migrate-v4` 推进 `state_revision`，并把前后修订号写入 `tracking_action`。纯格式/措辞调整才能用 `not_required`，且必须写理由。

4. 调用 `revision-governor`（`phase=verify`）读取当前 `active.json` 和所有关联产物。它返回 `READY_TO_CLOSE` 后运行：

```text
{PYTHON} scripts/revision_guard.py check --project {项目根} --input {项目根}/追踪/修改影响/active.json --stamp {项目根}/追踪/修改影响/active.approved.json
{PYTHON} scripts/tracking_commit.py check --project {项目根}
```

agent 复核、清单门和追踪门三者都通过之前，不得声称修改完成、发布修订章或继续写新章。`active.approved.json` 只批准它摘要绑定的那一版清单；验收后再改旧内容必须新开 change_id 和计划，不能复用旧审批。

hooks 的机械判定：

- 已提交章（章号不大于 `last_committed_chapter`）及既有总纲/卷纲/细纲/设定，没有 `active.json` 时拒绝写入；
- 活动事务未验收时，只允许写 `changed_files` 中列明的源文件，并阻止穿插创建未列明的新章/新纲；
- 审批戳与清单摘要一致后事务关闭，正常下一章可继续；再次修改旧内容必须建立新事务。

## 五、禁止的省事方式

- 只改正文，用“细纲只是参考”解释已经出现的反向口径。
- 只改总/卷/细纲，不检查已发表正文。
- 在 `关系清单.md`、`长期事实.md` 或实体档案中直接手改一行。
- 发现身世/血缘冲突后只改其中一个称谓，不检查祖辈、后代、姓氏、年龄、时间线和读者揭示范围。
- 用另建一份手写“最新版设定”解决冲突；这只会新增一个会过期的事实源。

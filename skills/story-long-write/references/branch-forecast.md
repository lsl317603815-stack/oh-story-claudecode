# 分支推演协议

分支推演用于降低高成本路线决策的返工，不用于证明模型更有创意，也不替代正式大纲。

## 术语边界

- **情节多线**：主线、感情线、阵营线、伏笔线等同时存在于同一正史方案。
- **分支推演**：从同一分歧点出发的多个互斥未来，只能选择一个进入正史。

输出时固定使用“分支推演”，不得把两者混称为“多线”。

## 启用门槛

满足下列任一硬条件，且存在至少两个因果上明显不同的可行方案时才启用：

- 决定影响至少后续三章。
- 改变人物身份、核心关系、阵营、秘密揭示或反派命运。
- 消耗不可逆的终局底牌、升级台阶或读者期待债。
- 选错后需要重做一个剧情单元、多个细纲或既有正文。
- 用户明确要求比较路线。

只有措辞、场景地点、出场顺序不同，或普通训练、过渡、信息收集章节，不启用推演。

## 层级

| 层级 | 分支数 | 视野 | 目标 |
|---|---:|---:|---|
| 总纲方向 `book` | 2-3 | 不展开逐章 | 比较核心引擎、主角道路和结局架构 |
| 卷纲 `volume` | 2-3 | 约 5-30 章 | 比较一卷的矛盾、储备消耗和终态 |
| 剧情单元 `unit` | 2-3 | 约 3-15 章，推荐 5-10 章 | 比较下一单元的完整因果链；默认首选层级 |
| 关键细纲 `chapter` | 2-3 | 1-3 章 | 比较近期关键行动及直接后果 |

总纲方向不得生成整本逐章分支树。细纲已锁定后，除非用户明确授权重规划，否则只报告分支差异，不修改已锁内容。

## 输入

至少加载：

- `设定/题材定位.md`
- `设定/题材契约.json`，存在时必读
- `大纲/大纲.md`
- 当前卷纲或相关剧情单元
- 相关角色、关系、伏笔和终局储备
- 连载中项目的 `追踪/上下文.md`
- 用户本次明确的作者意图

把会决定分支有效性的文件作为 `--base` 传入初始化脚本。脚本记录内容指纹，并在追踪状态存在时自动绑定当前 `state_revision`；任一基础文件或权威状态修订号改变，推演即为 stale。

## 输出比较维度

每个分支必须填写：

- 前提和关键人物决定。
- 按章或按阶段的行动、结果、反应、后续压力。
- 主角代理权变化。
- 读者契约兑现或损伤。
- 人物、关系、世界、伏笔的预计状态变化。
- 终局储备和期待债的消耗。
- 连续性、因果、人物动机和节奏风险。
- 与作者意图的匹配分及理由。
- 分支终态，以及它为下一单元打开什么。

方案必须因“人物选择和因果后果”不同而不同，不能只换事件皮肤。

## 运行协议

初始化示例：

```bash
for PYBIN in python3 python py; do "$PYBIN" -c "" 2>/dev/null && break; done
"$PYBIN" skills/story-long-write/scripts/outline_forecast.py init "{项目根目录}" \
  --level unit \
  --divergence "主角是否现在公开真实能力" \
  --author-intent "保持主角主动性，同时延后终极身份揭示" \
  --base "设定/题材定位.md" \
  --base "设定/题材契约.json" \
  --base "大纲/大纲.md" \
  --base "大纲/卷纲_第一卷.md"
```

脚本创建：

```text
大纲/推演/{forecast-id}/
├── forecast.json
├── selected-plan.md        # 只有选择后才生成
└── selection-receipt.json  # 绑定用户选择说明、分支摘要和上下文指纹
```

Agent 填写 `forecast.json` 中各分支，再运行陈旧检测：

```bash
for PYBIN in python3 python py; do "$PYBIN" -c "" 2>/dev/null && break; done
"$PYBIN" skills/story-long-write/scripts/outline_forecast.py check "{项目根目录}/大纲/推演/{forecast-id}"
```

## 选择与写回

只有用户明确说出选择哪个分支后，才能运行：

```bash
for PYBIN in python3 python py; do "$PYBIN" -c "" 2>/dev/null && break; done
"$PYBIN" skills/story-long-write/scripts/outline_forecast.py select "{推演目录}" \
  --branch B1 --confirm SELECT --approval-note "用户明确选择 B1"
```

`select` 没有 `--confirm SELECT` 和用户选择说明时直接失败；选择后只生成选择计划与选择凭证，不提供自动写回命令。选择分支和修改正式大纲是两次授权：

1. 用户选择分支，生成选择计划。
2. Agent 说明将修改哪些总纲、卷纲、剧情单元或细纲文件。
3. 用户确认改纲后，才把选择计划映射进正式大纲。
4. 映射后执行现有大纲安全检查和锁定规则。

推演目录永远不写入 `追踪/`。未选择分支不得被正文流程当作事实；已选择但尚未映射的分支也不得冒充正式大纲。

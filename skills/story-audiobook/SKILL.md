# Story Audiobook

把已定稿的章节变成多角色有声书。流程分两段：开书时选一次角并锁定，之后每章定稿后一条命令出成品（mp3 + 字幕 + 逐句清单）。

所有动作都由本 Skill 自带的 `scripts/audiobook.py` 完成。从当前 Skill 目录定位它，按项目统一方式探测解释器：`for PYBIN in python3 python py; do "$PYBIN" -c "" 2>/dev/null && break; done`。在作品根目录（包含 `正文/` 的目录）运行，或加 `--book <作品根>`。下文命令都省略了 `"$PYBIN" <Skill 目录>/scripts/audiobook.py` 前缀。

## 前置条件

- `ffmpeg`（macOS：`brew install ffmpeg`）。
- 火山方舟 **Agent Plan** 的 key：环境变量 `ARK_AGENT_PLAN_API_KEY`，或 macOS 钥匙串同名条目。脚本自己读取，**agent 不读取、不打印、不写入 key**；缺 key 时把脚本原话转给用户，让用户自己配置。Coding Plan 的 key 不含语音模型。
- 账号要在方舟控制台为语音模型开启 Agent Plan「抵扣」（只开抵扣即可，超额后付费不必开）。没开时合成报 `AgentPlanDeductNotEnabled`，脚本会给出操作提示，原样转告用户。
- 只能用豆包语音合成 2.0 的预置音色（`references/voices-seed-tts-2.0.json`，中文 90 个）。声音复刻 `seed-icl-2.0` 不在 Agent Plan 内。

先跑 `doctor` 看环境；第一次使用或怀疑开关没开时加 `--ping`（合成两个字）。

## 判断用户要做什么

| 用户说 | 去哪 |
|---|---|
| 开始做有声书、给角色选音色、试音 | A |
| 生成第 N 章（或一批章节）有声书 | B |
| 某句说话人错了、情绪不对、想换个读法 | C |
| 正文改了 | D |
| 现在做到哪了 | `status` |

### A. 选角（每本书一次）

1. `cast propose`：模型读 `设定/角色/*.md` 的外貌、性格、声线，给每个角色 3 个候选音色，写入 `有声书/选角候选.json`。第三人称书另给旁白候选；第一人称书旁白就是主角，锁定时自动同声。缺角色卡时先请用户补卡（至少写性别、年龄、性格、声线）。
2. `cast audition`：合成试音合集 `有声书/试音/试音合集.mp3` 和清单。每段前有报幕（「宋柚，候选一，邻家女孩」）。合成前把脚本打印的字数和 AFP 估算告诉用户。
3. **把试音合集交给用户听，等用户拍板**，不要替用户选。然后 `cast lock 角色=序号 …`；用户说「都用首选」时 `cast lock --all-first`。
4. 锁定后不再换声：已锁定的角色要换音色必须加 `--relock`，并提醒用户已出的章节会前后不一，需要重新合成。
5. 微调用 `cast set 角色 [--fx 电话|系统|心声|回忆] [--语速 N] [--音量 N] [--音高 N]`（语速、音量取 -50 到 100，音高 -12 到 12）。

后面章节出现新的具名角色时，`check` 会报「未选角」：对该角色单独走 `cast propose --roles 名字` → `cast audition --roles 名字` → `cast lock`。路人（接线员、店员这类）不用选角，标注时按性别和年龄段从路人池自动配音。

### B. 生成一章

1. 只做已定稿的章节：项目有 `追踪/` 时，要求 `追踪/章节提交/第NNN章.json` 为 `committed` 且正文没被改过。用户明确要先听草稿时才加 `--allow-uncommitted`。
2. 先 `make N --dry-run` 报估算：要新合成几行、多少字、约多少 AFP（豆包语音合成 2.0 每万字 1350 AFP，一章 3,500 字约 470 AFP）。用户要求生成即视为同意这笔用量；批量（`make 3-10`）先报总量再跑。
3. `make N`：需要时先标注（正文 → 有声稿），再校验，再逐句合成并拼接。
4. 汇报：成品路径、时长、本次计费字数与 AFP、缓存命中行数、存疑行（行首 `?`）、语速异常行。存疑行要请用户确认说话人。

`make` 内部等于 `annotate`（有声稿缺失或过期时）→ `check` → `synth`，也可以分步跑。

### C. 返修

- 说话人或情绪不对：直接改 `有声书/有声稿/第NNN章.有声稿.md` 里那一行的角色或〔表演指示〕，然后 `synth N`。只有改过的行重新合成，其余命中缓存。
- 文本没错、只是想换一次读法：`synth N --reroll 12,15`（行号见 `check` 输出、字幕序号或成品 `.json`）。
- 有声稿的文本必须与正文逐字一致，**不要在有声稿里改字、删字、调换顺序**；要改内容就改正文并重新定稿。

### D. 正文改了

正文重新定稿后，`make N` 发现有声稿过期会自动重标：没改的段落沿用旧的角色和指示（包括作者手改过的），只把改动段落交给模型；没改的句子直接命中缓存。

## 有声稿格式

一行一句，一句一个声部，人和脚本读同一份文件：

```markdown
---
章节: 1
标题: 凌晨的债
正文: 正文/第001章_凌晨的债.md
正文sha256: …
---
旁白〔章节标题，清晰稳重〕：第1章 凌晨的债

# 场1 凌晨便利店〔深夜静谧，日常松弛〕

旁白〔平稳舒缓〕：宋柚扎着丸子头，正拿漏勺撇关东煮格子里的浮沫：
宋柚〔轻快随意，带点好奇〕：学长，问你个事。

李清明·心声〔暗自疑惑，语气收紧〕：不对。那里明明只有一卷未拆封的热敏纸。
路人·接线员·电话〔急切询问〕：先生？患者现在情况怎么样？
?宋柚〔愣住追问〕：多低？
```

- 空行分段落，`# 场N` 开新场景；段内、段间、场间的停顿由脚本按规则插入。
- 变体：`·心声` `·电话` `·系统` `·回忆`，同一音色加后期滤镜。
- 行首 `?` = 模型拿不准说话人，作者确认后去掉。
- 生成方式是「切分交给代码，判断交给模型」：代码按引号和句末标点切片，模型只回「编号｜角色｜指示」，所以逐字忠实由构造保证；`check` 仍会逐字比对。

## 产物

```
<作品>/有声书/
  选角.json  选角候选.json  配置.json(可选)
  试音/                       试音合集与清单
  有声稿/第NNN章.有声稿.md      进 git
  成品/第NNN章_标题.mp3 .srt .json
  缓存/  工作/                 逐句音频与模型原始输出（自带 .gitignore，不进 git）
```

标注和选角的提示词分别在 `references/annotate-prompt.md` 与 `references/casting-prompt.md`，可按书调整；音色表在 `references/voices-seed-tts-2.0.json`（`voices 关键词` 可查）。

`配置.json` 可覆盖：`标注模型`（默认 doubao-seed-2-1-pro-260915）、`并发`（默认 4）、`场景上下文`（默认 false：实测听不出差别，且开启后一场之内只能串行）、`响度LUFS`（-18）、`峰值dBTP`（-3）、`码率`（192k）。

## 规矩

- 不伪造产物：没跑成功就说没跑成功，把脚本原话和 `explain` 给出的提示转给用户。
- 不替用户锁角、不擅自 `--relock`、不擅自对未定稿章节加 `--allow-uncommitted`。
- 有声稿只改角色、指示和存疑标记，不改正文文字。
- 汇报用量时以脚本打印的计费字数为准。

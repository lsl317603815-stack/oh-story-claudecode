# 采访协议（按模式）

每种模式给：依据文件、根的候选（开场第一题）、采访项清单（根定之后由功能拆解推出，不是固定模板）、本模式特有的追问点。通用的「密点追问」「功能拆解示例」「整段输入拆解示例」在文末。

路径约定：`{书名}/` 指项目内的书目录（story-long-write 结构）。依据文件**存在才读**，缺失不阻塞采访——候选来源降级并如实告知。对标资产从 `{书名}/设定/题材定位.md` 的「主对标书」字段解析，路径优先 `{书名}/对标/{主对标}/`，回退 `拆文库/{主对标}/`。

## 世界观

### 依据文件
- `{书名}/设定/题材定位.md`（读者契约、终局底牌、禁碰项；没有就先采它）
- 目标主题文件（草稿候选）；与之相关的其他世界观文件（找冲突）
- 对标同类设定：`{对标}/设定/世界观/*.md`；`{对标}/剧情/情绪模块.md` 的读者需求表与相关 EM 卡
- `{书名}/大纲/卷纲_*.md` 引用该主题的段落

### 根的候选（第一题）
- 主角为什么强（金手指 / 信息差 / 倍率来源）
- 世界为什么不对劲（大前提 / 核心悬念）
- 女主/关键配角在这套设定里是什么（来源 / 机制 / 与主线的绑定）
- 主线的重复动作/劳动是什么
- 按草稿主题顺序过（作者对草稿大体满意时）

### 采访项（根定后从功能拆解推出；下表是常见项，不是模板）
| 采访项 | 密/疏 | 问什么 |
|---|---|---|
| 主题定位 | 密 | 引擎、背景还是限制？删掉它故事还成立吗 |
| 核心规则 | 密 | 一句话规则；各知情方分别知道多少 |
| 可见形态 | 密 | 面板字段、公告句式、实物、价格——没有可见形态的规则不进正文 |
| 代价/边界 | 密 | 用它付什么；不能用在哪；边界谁定 |
| 隐藏层与揭示节奏 | 密 | 读者第几章知道全貌；中间用什么误导 |
| 与主线动作的关系 | 密 | 怎么接到主线循环；接不上就是孤立设定 |
| 与核心角色的关系 | 密 | 每个大件都过「跟主角/女主怎么绑」这一问 |
| 时间轴 | 密 | 关键事件落第几章 |
| 对手来源 | 密 | 梯队怎么排；终局宿敌是谁 |
| 命名与语汇 | 疏 | 术语、称谓；哪些作者层术语不进正文 |
| 社会观感 | 疏 | 各阵营分别怎么看主角 |
| 禁令 | 疏 | 正文不许怎么写；每条禁令单独问 |

### 本模式追问点
- 「这条规则局内人知道吗？」
- 「对标在同一位置怎么做，你要学还是反着来？」
- 「改了这条，卷纲第 X 章还成立吗？」
- 「这些数字互相对得上吗？」——放进全书体量算一遍，算不上当场亮（SKILL 纪律 17）

## 角色

### 依据文件
- 项目素材目录（如 `{书名}/参考资料/`）中该角色的原著/短剧/前作人设（保留项来源）
- `{书名}/设定/角色/{名}.md`（草稿候选）；`{书名}/设定/关系.md` 该角色的行
- 已定稿的世界观文件（角色不得与之冲突）
- `{书名}/大纲/卷纲_*.md` 该角色出现的单元卡
- 对标功能位：`{对标}/角色/` 对应角色

### 根的候选（第一题）
- 这个角色的**功能位**（对手/盟友/催化剂/见证者/靠山/系统）——身份被重定义的角色必从这里开始
- 他与主角的第一次交锋
- 他与全书核心悬念的关系
- 按保留项逐条确认（人设基本没变的角色）

### 采访项
| 采访项 | 密/疏 | 问什么 |
|---|---|---|
| 功能位 | 密 | 对手/盟友/催化剂/见证者/靠山/系统；换掉他谁能替 |
| 身份 | 密 | 表里两层身份；与核心势力的关系 |
| 保留项确认 | 疏 | 素材人设逐条勾 |
| 起点状态 | 密 | 首次出场的境界/等级/处境 |
| 动机链 | 密 | 起因→意图（表面/真实）→约束→风险 |
| 关键选择 | 密 | 本卷 1-2 个不可替代选择，第几章 |
| 对主角的态度曲线 | 密 | 起点→转折章（具体动作）→卷末 |
| 对核心悬念的态度 | 密 | 每个本卷角色都过 |
| 知情层级 | 密 | 知道什么、不知道什么（表格） |
| 语言指纹 | 密 | 2-3 句样例；自称；高压下声线 |
| 外形/标志动作 | 疏 | 保留为主，只问新增 |
| 写作禁忌 | 疏 | 不许写成什么 |
| 终点粗坐标 | 疏 | 后续卷一句话 |

### 本模式追问点
- 「他知道主角的底牌吗？知道了第一反应是什么？」
- 「他的靠山是谁？主角能借到吗？」
- 「改编源项目：他要有一场能拍的戏，是哪一场？」
- 系统型角色加问：声线规则、能做/不能做、资源额度在正文怎么显形、他自己想要什么

## 卷纲

> 提案先行+分段滚动（SKILL 纪律 21-23）：卷纲不逐章问细节；逐单元「整卡提案 → 1-3 个密点单题 → 整卡批」；先问验证关口再定前置骨架厚薄。

### 依据文件
- `{书名}/设定/题材定位.md`（终局底牌逐卷解锁表、透支红线）
- 已定稿的世界观/角色文件（已拍板的章节节拍直接作为单元卡输入）
- 现有 `{书名}/大纲/卷纲_*.md`（草稿候选）
- 对标：`{对标}/剧情/README.md` 单元清单、`节奏.md` 循环单元与高潮分布、`情绪模块.md`
- 卷纲模板：story-long-write 包内 artifact-protocols 参考的「卷纲」模板节

### 根的候选（第一题）
- 卷末大高潮是什么（倒推）
- 第一个大循环怎么切（对标常见 15-20 章一个「进场→被质疑→积累→大战→认证→转场」）
- 主线各轴的卷内里程碑
- 按已拍板的开篇节拍往后顺

### 采访项
| 采访项 | 密/疏 | 问什么 |
|---|---|---|
| 体量 | 密 | 多少章/多少字；改编源项目先问「对映第几季多少集」，集→章映射单独拍 |
| 卷契约 | 密 | 读者来看什么（一句话锥）；被驳时按功能拆解重出（每集重复爽/季级悬念/中点续期/身份落差/季尾钩五功能） |
| 主推线/战果 | 密 | 1 条主推线 + 战果线；女主线是否升格为并行强线（单元卡设进展栏）；禁碰复核 |
| 推进方式 | 密 | 「写完首段正文过谁的关」（外部/内部/不设关）→ 决定前置骨架厚薄与滚动切法 |
| 剧情单元切分 | 密 | 几个单元、各几章；粗地图先一行一单元过一遍 |
| 逐单元整卡 | 密 | **提案先行**：先摆整卡（承诺/情绪引擎/因果入口/阻碍/关键选择/兑现归属/各主线进展/每章一行功能），只对开着的密点出 1-3 题，再整卡批。⚠️ 每章只一行功能，不问卡点帧、不写台词 |
| 种子清单 | 密 | 必须埋进首段正文的长线种子逐条列出批过，进首单元卡种子栏；细纲逐章验收 |
| 对标结构坐标 | 密 | 1/4·中点·3/4 各落什么关键情节 |
| 情绪弧线 / 人物弧线 / 反转伏笔 | 疏 | 单元全部锁定后可由已拍板内容**机械导出**，落盘摘要里过目即可，不逐项采 |

### 本模式追问点
- 「这个单元删掉，卷末高潮还成立吗？」
- 「这个单元的爽点媒介和上一个单元重了吗？」
- 「这个单元喂了哪几条追看线？孤立的单场戏=观众不知道再看什么」
- 「改编源项目：这个单元是一集还是三集？」

## 细纲

> 提案先行（SKILL 纪律 21）：**每章先摆一版完整骨架提案**——情节点序列+卡点帧+台词锚+本章种子落位（卷纲种子栏对应项）——作者在提案上改，再按 A/B/C 过开着的密点；不从零开始逐题问。

### 依据文件
- 卷纲本章所属单元卡 + 情绪弧线本章行 + 伏笔表
- `{书名}/大纲/细纲_第{N-1}章.md`（真实承接）
- `{书名}/追踪/上下文.md`（长期约束、活跃伏笔、下一章承诺）
- 对标 EM 卡（本单元引用的）、`{对标}/剧情/节奏.md` 对应行
- 涉及角色的 `{书名}/设定/角色/{名}.md`、涉及设定的世界观文件
- 现有 `{书名}/大纲/细纲_第NNN章.md`（草稿候选）
- 模板：story-long-write 包内 workflow-setup 参考的「细纲（第 N 章）」节

### 根的候选（第一题）
- 这一章的爽点是什么（倒推）
- 章尾落在哪个画面
- 按单元卡节拍顺写
- 先定本章的核心可见变化（数字/关系/信息）是哪条

### 采访项（A 章头 → B 情节点 → C 收束）
**A. 章头（5-7 题）**：核心事件（密）/ 目标情绪（密）/ 主角目标与关键选择（密）/ EM+RH 召回（密）/ 本章核心可见变化（密）/ 章节定位与字数（疏）/ 禁止提前释放（疏）

**B. 情节点**：先出骨架一题确认（10-15 点，每点「谁做了什么【功能·密/疏·预算】」）；疏点一题留/改/删/并；密点第一题定发生什么，再按「密点追问」钻 2-4 轮。Σ 实时报。

**C. 收束（3-4 题）**：章尾落点（密）/ 收一个·变一个·开一个（密，各一题）/ 视角与信息差（疏）/ 契约风险（疏）

### 本模式追问点
- 「改编源项目：这一拍是一个镜头还是三个？」
- 「可见变化落地之后，下一个可量化目标是什么？」
- 「在场配角谁第一个开口？说什么？」
- 「信息差/内心戏直给的那一句是什么？」（直给型项目问到具体的那句）
- 「碰禁碰项了吗？」

## 密点追问（通用）

拍板一个密点后挑 2-4 个往下钻，问到「正文写手不用猜」为止：
1. **触发**：谁/什么触发？不在主角手里时亮代理权风险
2. **在场**：谁在、谁不在；不在的人之后怎么知道
3. **可见变化**：哪个数字/关系/信息变、变多少；不变为什么压着
4. **反应层**：各阵营分别看什么；谁第一个开口
5. **反方向**：反过来这一章还成立吗
6. **边界**：碰禁碰项了吗
7. **镜头**：改编源项目用什么做锚（物件/动作/一句话）
8. **后账**：给后面留了什么账

## 功能拆解示例（实战改写）

作者：「不要人人能干的苦力，你需要从第一性原理出发，思考设计叙事功能性上的替代。」

错误做法（被驳回）：照抄对标「挖矿」的形式，出一个换皮候选。

正确做法：先拆功能——

| 挖矿承担的功能 | 对标做法 | 本书接手者 |
|---|---|---|
| ① 确定性节拍 | 挖一天→面板跳 | 已有引擎接住 |
| ② 身份锚 | 矿工→监事→捕快 | 空缺 |
| ③ 资源管道+滚雪球 | 矿石→钱→镐→更多矿 | 空缺 |
| ④ 舞台 | 矿场 | 现有舞台只撑到前期 |
| ⑤ 品格证明 | 肯干别人不肯干的活 | 主角的独特品格接住 |
| ⑥ 工具即武器 | 镐凿穿护体功 | 删 |

再从空缺推候选：设计一个能同时接住②③④⑤的主线循环。作者在候选基础上加了自己的机制——候选是起点，不是终点。

## 整段输入拆解示例（实战改写）

问的是一个单点，作者自由输入给了 600 字的世界观（身份、金手指来源、权限层级……）。

正确处理顺序：
1. 原话逐字入账为一行（决定 N），备注栏列连锁影响（哪些旧前提作废、哪些新缺口打开）
2. 重排待定清单：作废被回答的项，新增这段话打开的缺口
3. 下一题**不复述全文**，只复述一句理解 + 一个最关键的缺口
4. 之后每题都从作者这段话里长出来，候选用他的词

反例：把 600 字压成一个候选「按你说的来」让作者点——那是把他的设计还给他，不是采访。

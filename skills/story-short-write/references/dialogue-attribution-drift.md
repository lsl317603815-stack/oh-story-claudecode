# 对白归属标记漂移 Gate

本 Gate 只承担机械定位，完整生成与语义审查方法以 [适度对白技巧](dialogue-craft-moderate.md) 为准。标签密度、动词集中度和跨章偏移只产生预警，不得单独判定对白不合格；只有明确的连续逐句报幕等阻断项才返回非零。

## 问题定义

“张三说”“李四问”本身不是坏句式。真正的问题是长篇写到后段后，这类标记开始高密度、连续、同构出现，人物对话变成逐句报幕。

这属于长程文风退化，而不是单句语病：

1. 上下文压缩后，模型保留剧情事实，却容易丢失前几章的表达分布。
2. 为避免读者分不清说话人，模型反复选择最安全的“人物名 + 说/问”。
3. 现有检查逐句判断，每一句都合法，因此发现不了章节级累积。
4. 如果只提示“少用说问”，模型又可能改成“沉声道、冷声道、缓缓开口”等同样模板化的同义替换。

## 验收链路

正文初稿先过中文语言 Gate，再运行：

```bash
node scripts/dialogue_drift_gate.js \
  --current "正文/第091章.md" \
  --history-dir "正文"
```

检测器同时查看：

- 本章显式归属标记占对白轮次的比例。
- 连续对白行是否都带“谁说/谁问”。
- 同一动词及“说类/问类”动词族的集中度。
- 本章与最初三章文风基线的差异。
- 本章相对最近三章是否突然恶化。

存在 `advisories` 时继续进入适度对白语义审查；返回非零时，将阻断指标、行号、原片段和所在行退回产生本章的正文写作者。修改后重新运行，返回码为零才可继续后续流程。

## 正确回修

根据语境混合使用以下方式，而不是机械替换所有“说/问”：

- 双人轮流对话且说话人明确时，省略归属标记。
- 用真正推动场景的动作、停顿、视线或物件交互承接对白。
- 用对方的反应承担说话人切换。
- 让人物词汇、句长和语气本身具有辨识度。
- 只有发生歧义时保留简洁的“某某说/问”。

禁止把所有“说”替换成“沉声道、冷声道、缓缓说道”，也禁止为了降指标给每句对白强塞无意义动作。

## Gate 顺序

```text
正文初稿
→ 中英文混杂 Gate
→ 对白归属漂移 Gate
→ 适度对白语义审查
→ 去 AI 味与退化检查
→ 审查与追踪提交
→ 下一章
```

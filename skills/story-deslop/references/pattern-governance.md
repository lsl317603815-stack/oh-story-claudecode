# 去味模式治理

模式清单是可证伪的编辑假设，不是“真人写作法典”。命中只说明需要看语境，不等于作者一定使用了 AI。

## 三类规则

| 类型 | 处理 | 例子 |
|---|---|---|
| 确定性硬门 | 高置信且边界明确，可 blocking | 未授权英文泄漏、项目明确禁止的毒句式 |
| 语境规则 | 默认 advisory，必须结合场景和功能 | 排比、短句、破折号、重复、心理直述 |
| 结构假设 | 只允许语义审计，不自动改 | 人物声线趋同、全文节拍同构、反复解释意义 |

规则至少包含 `id`、`scope`、`semantic_risk`、`signals`、`exclusions`、`preservation`、`auto_fix` 和 `evidence_status`。机器可读候选见 [模式契约](pattern-contracts.json)。

## 误杀边界

- 排比可能承担审判感、誓言、口号或人物强迫性思维。
- 重复可能承担创伤回响、线索确认、节奏或人物口头禅。
- 心理直述可能是儿童视角、第一人称自欺或关键认知变化。
- 破折号、碎句和省略可能属于作者稳定文风。
- 对话完整可能来自职业、身份或正式场景，而非声线趋同。

命中排除条件时保留，并在保护账本记录其功能；不要用白名单把整个模式永久关闭。

## 模式晋级门

新增或升级自动修复规则前，至少准备 50 份同题材、同篇幅级别样本：25 份确认有问题的 `hot` 样本和 25 份真人作品或用户认可正文的 `human control`。自动改写规则精确率目标不低于 0.80，召回率目标不低于 0.50，不允许破坏剧情事实、人物声线、伏笔或正式文体。每个模式必须有正例、反例、排除条件、保留说明和改前改后样例。

未达到门槛时保持 `candidate/advisory`，不得把 GitHub 星数、AI 检测器分数或少量示例当作有效性证明。

## 方法来源

本协议借鉴以下 MIT 项目的可复用思想，并按小说连续性重新实现：

- `MrGeDiao/shuorenhua`：保护片段、事实关系账本、严重度与改写范围分离。
- `devswha/patina`：语义风险、排除条件、保留说明和正反样本治理。
- `awnist/slop-cop`：机械、局部语义、全文结构分层。
- `blader/humanizer`：声线样本优先于通用规则。

`orange2ai/renwei-writing` 与 `NulightJens/humanizer-stack` 未明确许可证，只借鉴抽象方法，不复制文本或代码。

# 小说去味保护账本

保护账本回答“改写后哪些叙事事实、信息边界和作者手迹必须仍然成立”。

## 硬保护项

- 人名、地名、组织、物件、功法、型号及其他专有名词。
- 数字、日期、章数、距离、金额、年龄、等级和数量关系。
- 谁做了什么、对谁做、是否完成、付出什么代价。
- 人物此刻知道什么、不知道什么、误解什么。
- 已发生事实与角色猜测的边界。
- 伏笔原始信息、误导方向、回收条件和未公开部分。
- 对话中承担身份、关系或立场变化的关键词。

## 软保护项

- 角色高频词、句长、停顿方式和回避习惯。
- 作者有意保留的重复、碎句、方言、冷幽默和不对称表达。
- 叙述视角能看见、听见和推断到的范围。
- 场景已经建立的情绪落点和留白。

软保护项不是逐字冻结，但不能把不同人物磨成同一种“自然口语”。

## 账本结构

`deslop_guard.py init` 自动提取数字、书名号内容和行内代码，其余字段由 Agent 根据项目设定、细纲和追踪补全：

```json
{
  "version": 1,
  "auto": {"numbers": [], "titled_terms": [], "inline_code": []},
  "manual": {
    "protected_literals": [],
    "entities": [],
    "timeline_facts": [],
    "knowledge_boundaries": [],
    "clues": [],
    "voice_markers": [],
    "intentional_roughness": []
  },
  "allowed_changes": []
}
```

`allowed_changes` 用于明确允许的等价变更，例如：

```json
{"from": "3", "to": "三", "reason": "对话口语格式统一"}
```

没有登记的数字、专名和硬保护短语在候选稿中减少时，脚本按 blocking 报告。

## 声线校准

项目存在已认可章节时，按人物各取少量真实样本，记录句长、省略主语、回避方式、情绪高点反应、专属词汇和稳定语法毛边。样本只用于保护差异，不用于逐句仿写。没有样本时不虚构“作者声线”。

## 保真审计

1. 每个硬保护事实是否仍可定位。
2. 主体、动作、对象、完成态和代价是否改变。
3. 人物是否提前知道本不该知道的事实。
4. 伏笔是否被解释、强化或削弱到改变未来回收。
5. 不同人物的对话是否被统一成完整、正确、会总结的句子。
6. 作者有意留下的毛边是否被无理由磨平。

任何一项失败，先恢复事实或声线，再继续残留味审计。

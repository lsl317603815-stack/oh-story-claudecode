# 已接纳正文声音画像协议

声音画像解决的是“这段文字是否偏离这本书已经成立的声音”，不解决“所有小说应该怎么写”。它是通用去 AI 味规则之上的本书局部基线，必须与具体作品解耦：工具只提供 schema、统计方法和门禁，样本与画像始终留在当前项目。

“已经接纳”只代表正文成立，不代表每章都同样值得模仿。因此本协议把**已接纳基线**与**黄金声线样本**分开：前者防止漂移，后者由作者从已接纳正文中精选，提供更窄的质量方向；两者都只作 advisory。

## 可信样本

画像只接受两类来源：

1. `追踪/章节提交/第NNN章.json` 状态为 `committed`，且 `accepted_prose_sha256` 与正式正文一致的章节。
2. 没有历史回执的旧项目，由作者显式声明“已批准到第 N 章”的连续旧章范围。

候选稿、废弃分支、未闭环回执、备份/归档目录、对标作品和外部语料都不得混入本书画像。旧章范围不能由 Agent 从“正文文件存在”自行推断。

至少需要五章可信样本。样本不足时继续执行通用语言门、毒句式门和退化检查；不得用一两章制造伪精确文风。

## 派生产物

脚本生成：

- `追踪/文风/accepted-voice-profile.json`：机器读取的来源摘要、逐章统计、早期/近期窗口和原句哈希。
- `追踪/文风/accepted-voice-profile.md`：作者可读摘要。
- `追踪/文风/golden-voice-profile.json`：作者精选章节的机器画像。
- `追踪/文风/` 下的黄金样本作者可读摘要（文件名为 golden-voice-profile.md）。
- `追踪/文风/盲测/{id}/` 下的盲测正文包：隐藏来源标签，供独立冷读。
- 同一目录的答案文件：冷读完成后再打开。

这些都是 `voice_profile.py` 的派生产物，不得手改。画像不复制整章正文，只保存正文路径、哈希、统计量与用于原句重合检查的单句哈希。

## 生命周期

先探测可用 Python，再按当前 skill 目录执行：

```bash
for PYBIN in python3 python py; do "$PYBIN" -c "" 2>/dev/null && break; done

# 新项目：已有至少五个 committed 回执
"$PYBIN" scripts/voice_profile.py build --project "{项目目录}"

# 旧项目：作者已经明确批准第 1—N 章作为本书文风样本
"$PYBIN" scripts/voice_profile.py build --project "{项目目录}" \
  --legacy-approved-through N --confirm LEGACY_APPROVED

# 候选稿检查；advisory 不阻断接纳，过期画像会阻断
"$PYBIN" scripts/voice_profile.py check --project "{项目目录}" \
  --candidate "{候选正文}"

# 新章接纳、回执与追踪全部闭环后更新
"$PYBIN" scripts/voice_profile.py update --project "{项目目录}"

# 发布/续写前验证画像仍绑定当前接纳正文
"$PYBIN" scripts/voice_profile.py verify --project "{项目目录}"

# 可选：作者从已接纳正文中精选黄金样本；至少 5 章，建议 8—12 章
"$PYBIN" scripts/voice_profile.py golden-build --project "{项目目录}" \
  --chapters "3,8,15,22,31,44,57,70" --confirm GOLDEN_APPROVED

"$PYBIN" scripts/voice_profile.py golden-verify --project "{项目目录}"
```

`chapter_candidate.py check` 已自动调用候选检查。画像存在时，新接纳回执会使旧画像变为 `stale`；因此正确顺序是：候选检查 → 用户接纳 → 正文/追踪/回执闭环 → `voice_profile.py update` → `story_doctor.py`。不能先把候选稿吸收进基线，再用被它改变过的基线检查自己。

## 双向漂移语义

脚本观察段落、句子、分句、对白段、标点、少量高风险连接词与章内原句重复等可机械量化项。候选值只有在同一方向同时超出“早期窗口”和“近期窗口”的实际样本范围时才报告 `voice-drift`。

- 偏高与偏低都报告，避免把“越少越自然”误当真理。
- 报告是 `advisory`，不是质量分；超出范围可能是高潮、梦境、书信、审讯或人物崩溃等有意变奏。
- 不得为了回到均值机械增删短句、对白、逗号、比喻或生理反应。
- 先定位具体段落，判断场景功能、人物声线、叙述距离和节奏目的；只有读感确实受损时才改。
- 画像过期属于数据来源错误，因此阻断使用；这不等于画像中的风格提示变成硬性审美门。

原句重合检查只提醒候选与已接纳正文的较长句子完全重合。固定口头禅、规则宣告和必要回环可以保留；普通叙述的无意复用再改。

## 黄金声线样本

- 只能从当前 fresh 的已接纳基线中选择，不能直接纳入候选、对标作品、备份或未闭环章节。
- 至少 5 章，建议 8—12 章；选择应覆盖不同场景压力，不要只挑同一种高潮或对白章。
- `golden-build` 必须记录作者明确选择，并使用 `GOLDEN_APPROVED`；Agent 不得从阅读偏好自行推断。
- 候选检查同时输出已接纳基线漂移和黄金样本漂移。两者方向不同并不矛盾：候选可能仍像本书，但离精选强样本较远。
- 黄金样本不是固定模版。高潮、梦境、书信、审讯和人物崩溃等功能性变奏可以超出范围，记录理由后保留。
- 新章接纳不会自动进入黄金样本；只有作者再次精选并显式重建时才改变黄金集合。

## 盲测与 A/B

当统计提示很多、作者与 Agent 判断不一致，或准备把新模式升级为通用规则时，生成盲测包：

```bash
"$PYBIN" scripts/voice_profile.py blind --project "{项目目录}" \
  --candidate "{候选正文}" --id "{评测编号}" --confirm PREPARE
```

让未参与改写的人或独立阅读 Agent 先只读盲测正文包，不打开答案，逐段回答：

1. 是否像同一本书；
2. 哪个词、句群或叙述动作让人出戏；
3. 差异是否可能由当前场景功能解释；
4. 哪一版更想继续读，理由是什么。

完成记录后再打开答案。单次“猜中 AI”不能升级规则；只有跨章节、跨读者反复出现且能定位到具体文本机制的结果，才能按 `pattern-governance.md` 进入观察、advisory、blocking 的证据升级流程。

## 修订与旧章变化

- 有回执章节完成合法修订并同步 `accepted_prose_sha256` 后，画像会变旧；修订门闭环后运行 `update` 重建。
- 仅凭旧章显式批准纳入、但没有回执的样本一旦变化，`update` 不会静默吸收。必须重新冷读该范围，并再次用 `build --confirm LEGACY_APPROVED` 授权。
- 修改画像脚本、指标含义或 schema 后，旧画像必须重建；不得把不同算法版本的范围直接拼接。

## 首版明确不做

- 不自动判定角色专属声线；对白归属解析不足时容易把人物混在一起。
- 不声称检测“AI 概率”或“真人率”。
- 不用跨书固定比例替代本书样本。
- 不因统计漂移自动改正文。
- 不把单次平台数据波动或单次盲测结果写成通用硬规则。
